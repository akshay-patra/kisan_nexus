1. security/
Purpose

Handles application security and RBAC.

security/
├── SecurityConfig.java
├── JwtService.java
└── CustomUserDetailsService.java
File	Type	Why needed
SecurityConfig.java	Security config	Defines which APIs require authentication and which roles can access them
JwtService.java	Service	Creates, validates and extracts information from JWT tokens
CustomUserDetailsService.java	Service	Loads the authenticated user for Spring Security
No Entity / Repository / Controller

Because security is infrastructure rather than a business domain.

Later:

FARMER → /farmer/**
FPO    → /fpo/**
BUYER  → /buyer/**
ADMIN  → /admin/**

And Spring Security becomes the actual enforcement mechanism.

Purpose

Handles:

Mobile Number

OTP
      ↓
Verification
      ↓
JWT

Structure:

authentication/

├── dto/
│   ├── SendOtpRequest.java

Files
File	Type	Purpose
AuthenticationController	Controller	/auth/send-otp, /auth/verify-otp
AuthenticationService	Service	Coordinates authentication flow
OtpService	Service	Sends/verifies OTP through OTP provider
SendOtpRequest	DTO	Phone number coming from frontend
VerifyOtpRequest	DTO	Phone + OTP
AuthenticationResponse	DTO	Returns JWT/user information
No Repository

Because the actual user persistence belongs to users/.

Supply

        ↓

Because a "match" doesn't necessarily need to be permanently stored for your MVP.

                ↓

       AiLogisticsClient
                ↓
      Python AI Service
                ↓
          OR-Tools
                ↓
       Optimized Route
Why no Repository initially?

Because the MVP can generate an optimized route from current order/logistics data without necessarily persisting every optimization calculation.

If you later want persistent route history:

DeliveryRoute.java
RouteStop.java
DeliveryRouteRepository.java
RouteStopRepository.java

can be introduced.

Don't create them unless the MVP actually needs route persistence.
